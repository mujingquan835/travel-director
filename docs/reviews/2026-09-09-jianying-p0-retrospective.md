## 为什么错

台账原判断“GUI creation is the only verified compatibility path”缺乏闭环证据。观察到已有草稿为非明文，不能推断新草稿不能程序生成。没有先查开源项目、做最小格式兼容实验，就进入大量界面操作，这是路线选择失误。将用户要求的打开、编辑、保存验收扩大成全程鼠标剪辑；又在格式可行性未确定前加了计划、子任务、全量基线和预览器建设，放大了成本。没有设置 GUI 重试及时间上限。

## GitHub 一手调研

- https://github.com/GuanYixuan/pyJianYingDraft ：当前 README 标注 10.8 的视频、音频、音量、时间控制等支持；模板读取另需 fallback_loader。跨平台说明仍强调 Windows 导出，不能据此保证 macOS 11.4.0 可打开。优先作为最小写入实验候选。
- https://github.com/GuanYixuan/pyJianYingDraft/issues/177 ：macOS 10.3.0 生成 demo 后报内容损坏的公开问题，提示必须分开验证生成成功与客户端可用，不证明 11.4.0 必然失败。
- https://github.com/sun-guannan/VectCutAPI ：原 CapCutAPI 重定向至此，提供创建、添加音视频、保存 API/MCP；jianying_pro_10 配置说明为 Windows 风格目录。云渲染等部分未开源。可参考接口，但不能当成本机兼容保证。
- https://github.com/Hommy-master/capcut-mate ：FastAPI 草稿管理、批量素材、音频和参数接口，可独立部署。适合作为接口设计或备用适配器候选；本轮没有运行验证。

## 下一步实验与停止条件

1. 冻结现有三段视频、音乐、两个本地音效，只读取这六个文件的必要元数据，不重扫素材。
2. 首选固定 commit 的 pyJianYingDraft，审查依赖与写入路径，在隔离目录生成 12 秒草稿：视频 3×4 秒；独立音乐轨；两个音效片段；明确音量与源音静音。先不做模板解密、花字、自动 MP4 导出。
3. 程序检查素材存在、源时间不越界、总长、轨道、音量、草稿引用及资源打包。输出状态仅为 draft_generated。
4. 只在验收时打开生成草稿：检查轨道、播放音频、编辑一处、保存重开。尊重用户当前反对鼠标制作；验收优先由用户在剪映里做一次，自动 UI 验收需要重新明确范围，不能变成手工修片。
5. 建议首个兼容实验上限 20 分钟，最多两次有明确格式依据的修正。失败则保留错误与样本，状态 incompatible_or_unverified；不退回鼠标拼装，不反复尝试相似 fork。再比较明确支持的客户端/平台或替代交付。
6. 只有上述通过后才封装 Skill/CLI。Skill 负责 brief、调用和验收门槛；脚本负责草稿结构、ID、资源路径、时间单位与参数合法性。不要让模型逐字段输出完整剪映 JSON。

## 对截图的取舍

采用“接口化执行、模板按需检索、首轮成型、第二轮局部修改”的方向。模板库存只给模型精简标签和可调参数，选中才加载细节。两轮是正常路径目标，不是质量保证；不合格时返回具体问题。音乐变更重算音乐分析和时间线，复用素材语义索引。音效必须有真实文件、时间位置、音量和混音预听。低成本视觉模型是否胜任用小规模标注样本对比，不未经评测直接换最弱模型。
