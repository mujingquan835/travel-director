日期：2026-09-10。阶段：附件、当前安装版 Skill、绑定源码与参考创作资料核查完成；本文为调整建议，未修改 Skill 或程序，未制作新样片。

## 判断与证据边界

当前更需要补的是镜头级音画决策，而不是增加一份宏观叙事表。已有段落规划、音效落轨、可编辑交付，不等于动作连接、声音质感和乐句组织已经成立。

本轮未收到用户明确指定的不满意成片/草稿路径，不能断言该片哪一秒出错，也不能确定音乐就是主要原因。已异步询问草稿名称或路径。参考片依据作者原发布页和两份作者访谈；本轮没有对原片进行逐镜头观看或听觉审片，因此下文的参考方法属于作者陈述，示例属于方案，不伪装成实看片段记录。

## 附件应吸收什么

输入：`<downloads>/抖音Vlog音效节奏教程_观点梳理.md`。其中步骤是参考教程内容，不是本次执行指令。

保留：先处理音乐结构；波形与试听分开；强弱对比和停顿；音效重音对齐视觉事件；快切与长镜头形成对比；最后回看音画组合。

不固化为通用规则：人物必须在左下角、8 个快切、每段 4 帧、每刀 whoosh、3–5 拍一镜、故障三连、固定黑场。这些依赖题材、素材与时间基准。4 帧在 25 fps 是 0.16 秒，在 30 fps 约 0.133 秒；不能忽略帧率直接复制。附件不同段落对“节拍点/半拍”的表述也不适合直接作为机器时长合同。

“波峰对齐”应改成“听感明确的声音事件对齐”：最大振幅未必就是希望观众感知的撞击或转折，长音的峰值也不一定适合作锚点。

## 《土耳其瞭望塔》应学什么

原片：[Leonardo Dalessandri — Watchtower of Turkey](https://www.youtube.com/watch?v=z7yqtW4Isec)，原发布说明署名音乐为 Ludovico Einaudi 的 Experience。这不是建议当前项目直接采用该曲。

[FCP 作者访谈](https://fcp.co/final-cut-pro/articles/1582-watchtower-of-turkey-a-stunning-piece-of-cinematic-editing-and-sound-design-created-in-final-cut-pro-x-gets-nominated-best-of-vimeo-2014) 中，导演说明先组织配乐，把多个音乐版本剪混成所需情绪；按动作、内容和颜色寻找相邻镜头；使用现场录音与素材库声音，并让很多环境层轻微融入音乐。可迁移的是声音连续性与镜头匹配，层数不是指标。

[Musicbed 作者访谈](https://www.musicbed.com/articles/filmmaking/directing/the-music-of-film-a-conversation-with-leonardo-dalessandri/) 中，导演解释拍摄后一个场景时会记住先前镜头的运动方式，以便连接，也强调人物与静默的价值。这说明后期手法依赖素材覆盖；若现有素材主要是同景别风景，Skill 应改用可实现的表达，并列出缺少的人物、动作或细节镜头。

已有显式 `clips` 路径允许指定 source_in 和独立音轨，因此并非整个系统都不能提前放音或选声音中段。上述锚点限制特指自动 sfx_cues 路径。已有音乐片段也能分段排布；缺的是乐句决策证据与平滑混音表达，不能重复开发成“首次支持音乐剪辑”。

## 建议的新工作顺序

素材快速粗看 → 初步情绪和叙事目的 → 用户选曲 → 音乐乐句与声音空间草案 → 少量候选镜头精看 → 镜头连接与动作落点 → 环境声/拟音/设计音 → 小样审片 → 完整可编辑交付。

音乐和画面允许迭代。不是把音乐完全定死后才看素材，也不是把原叙事秒数强塞给任何音乐。用户已明确要求的时间或顺序仍作为约束；冲突显式报告。

建议分五项改动：

1. **增加候选镜头精看。** 沿用现有 3–5 帧粗看及 compact JSON 机制。只有入选或连接有疑问的短区间，才读取连续低清片段/更密时间样本。保存 source_in/out、景别、主体位置、镜头与主体运动方向、动作起始/重音/结束时刻、可信度和证据。连续运动与精确时刻不能由稀疏静帧臆测。不要把新字段硬塞进当前八字段合同。
2. **先组织镜头组。** 在宏观段落下增加局部序列：交代空间、进入动作、细节、反应/结果、释放等按素材选用的职能。每次关键连接说明依据：动作、方向、视觉注意点、颜色/形状、内容、声音桥或有意反差。不强求所有切换都无缝，但应能解释为什么此刻切到这里。
3. **音乐从卡点提升为乐句适配。** 保存原曲区间到项目区间的对应表、转折、停顿、结束处理和听审状态。自动能量标签不升级为已确认乐句。新增修订路径保存前后差异，不直接改冻结历史。速度不必等于 BPM：长镜头内部的动作也能响应音乐，快切只占有理由的局部。
4. **音效从“选文件”提升为“设计声音事件”。** 每条 cue 描述画面原因、角色、听觉前后景、声音源内事件锚点、预响与尾音、包络及与音乐的关系。优先现场/合适环境声建立场所，再按需要突出动作，最后才添加抽象转场。现场声不可用应标缺口；库拟音不得伪称现场录音。高频 whoosh 不应成为默认。
5. **交付增加实际听看验证。** 验证程序、剪映兼容、主观音画质量三者分别记录。先看无音乐画面是否成立，再听声音是否有空间与层次，最后合看是否有竞争和错位。声轨数、非静音检测、峰值指标及测试通过都不能替代听感。

## 声音锚点示例（拟议合同，不是现有参数）

假设已经观察到视觉事件在项目 8.00 秒；选中音效在源内 0.35 秒有需要的声音重音，源入点为 0：

`音效时间线起点 = 视觉事件时间 - (声音源内锚点 - source_in) = 7.65 秒`

当前自动 cue 若从 8.00 秒播放，会让该重音落在 8.35 秒。这个例子只说明可能的错位机制，不代表实际草稿已测得该误差。变速时还必须应用时间映射，不能继续用原速公式。起点越过项目头尾需明确处理，不能裁掉前奏后仍声称锚点不变。

建议扩展字段：`event_time`、`source_anchor_time`、`source_in`、`pre_roll`、`tail_policy`、`gain_envelope`、`selection_reason`、`listening_status`。其中可推导项由程序计算，避免互相矛盾。声音锚点可先由局部检测提出候选，再经试听选择；不得一律取全文件最大波峰。

## 可写入 Skill 的规则草案

以下为后续修改文本，不代表现有实现已支持：

> 宏观分段后，先规划相邻镜头的联系与观众注意点，再决定切点和音效。不得以“符合主题”代替镜头连接理由。
>
> 粗看只负责筛选。精确动作、剪辑区间和运动匹配必须有入选区间的时间证据；证据不足时选用更简单的剪法，或追加局部观察。
>
> 音乐节拍、能量变化和候选小节首拍是定位提示。乐句、乐器、情绪和终止感分别记录听审来源；未听审不得宣称已确认。
>
> 每条设计音效必须有具体功能。仅因换镜头，不自动添加 whoosh 或 hit。先决定何处应听到场所、人物和动作，再决定何处需要强调与静默。
>
> 对齐声音事件而非文件起点。检查预响、重音和尾音，明确何时音乐应让位。导出能力不能表达的处理标记为待实现，不用文字冒充已落轨。
>
> 对相同素材优先做小样比较；保留当前成片基线和同音乐版本，确定主要问题后再试替代音乐。审美结论须有实际听看反馈。

## 最小验证方案与优先级

第一步先做 15–20 秒局部验证，选能包含一处动作连接、一处环境转换或情绪转折的连续段落。时长是实验建议，不是固定剪辑模板。

| 版本 | 保持不变 | 改动 | 判断 |
| --- | --- | --- | --- |
| A 当前基线 | 当前素材、音乐、音效 | 无 | 定位现状 |
| B 画面修订 | 同一音乐区间和音乐处理 | 重排/精修画面；只保留可对应原事件的声音，移除失去锚点的声音并记录 | 镜头联系是否改善 |
| C 声音修订 | B 的镜头与音乐选择 | 事件锚点、环境连续、拟音、必要的音乐让位 | 是否更可信、更有呼吸 |
| D 可选换曲 | C 的画面与音效，试听响度尽量一致 | 经用户选择的替代音乐 | 初步比较音乐情绪适配；若需重剪才能适配，另记适配版本，不能当单变量比较 |

初始开发优先：局部时间观察 + 镜头连接表 + 自动 cue 锚点/包络。随后完善音乐适配修订与真实重拍/乐句候选标记。高级变速、遮罩、故障特效后置；不用效果数量证明质量。

性能：复用原有扫描与观察，只处理选中区间；缓存按源哈希与区间建立；不全量重扫、不另起模型调用、不重新写冗长观察 JSON。时间、token 与主观效果分别记录，未测试不承诺开销数值。

验收：观众能读出局部事件；关键连接有依据；动作音无可感错位；环境声不随每刀重启；音乐与声音不长期争抢前景；对比版本得到实际听看反馈；新增包络/源内锚点在导出和剪映保存重开后仍正确。程序测试重点应验证时间映射、项目边缘、尾音、包络往返与旧合同兼容，不测试审美打分。
