# 调用方智能体模型策略

日期：2026-08-31

状态：`accepted`

## 决定

“旅行导演”后续以 Skill 形式运行时不绑定模型。Skill 由哪个智能体调用，就使用该智能体当前配置的默认模型和已有视觉能力。

项目代码和 Skill 均不得：

- 写死 Codex 型号、第三方模型名或 API endpoint；
- 为画面理解递归创建另一个智能体任务；
- 把模型名设为 Schema 必填字段、素材身份或缓存命中条件；
- 在调用方不能读图时静默切换到其他付费模型。

## 稳定合同

模型可以变化，但下列合同保持不变：

1. Scanner 本地生成元数据、CV证据和每条素材 3—5 张代表帧。
2. Skill 将单条素材代表帧合成一张联系图，每批最多处理 10 条。
3. 当前智能体只输出严格 `ClipObservation` 候选字段，不判断具体地点、人物身份、最佳区间或最终素材职责。
4. 每批结果立即保存独立 JSON 检查点；失败可从最后成功批次恢复。
5. 低置信度、冲突和影响导演判断的未知字段进入人工确认。
6. 调用方没有视觉能力时，返回明确能力状态并走 `scanner_only + assisted`。

## 可审计信息

若运行环境能够提供实际模型名称、智能体类型、耗时或 token，可作为可选运行元数据记录。缺失这些信息不阻塞合同，但不得伪造或用静态配置代替实测。

## 原因

本地 Qwen3-VL 4B 候选已因内存硬门不合格。绑定另一个具体云模型会把成本、权限和可用性重新变成单点依赖；继承调用方智能体模型可以复用用户已有额度，同时保留 deterministic Director 和人工确认回退。
