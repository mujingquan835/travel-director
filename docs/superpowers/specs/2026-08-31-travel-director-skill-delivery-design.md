日期：2026-08-31

状态：待用户复核

分支：`feature/local-media-scanner-v0.1`

## 1. 结论

旅行导演第一阶段的最终产品入口是 Codex Skill，而不是需要用户持续打开的本地 Web 应用。

最终调用方式为：

```text
$travel-director
```

用户只需提供素材目录和旅行表达描述。Skill 负责调用本地 Scanner、组织代表图、使用当前调用它的智能体完成受控画面理解、执行 deterministic 导演规则，并在当前对话中返回导演方案和三条音乐生成提示词。

本地页面仅是条件式人工复核工具：只有待确认项较多、不适合在对话中逐条确认时才生成并打开。它不是首页、不是常驻服务，也不是用户每次使用的必经步骤。

## 2. 产品边界

### 2.1 第一阶段交付

- 一个正式安装的 `$travel-director` Skill。
- 素材目录扫描与可恢复项目状态。
- 当前调用方智能体对受控联系图的分批理解，不绑定具体模型。
- 用户描述规范化和必要确认。
- 五桶素材判断、项目覆盖、导演主线、章节、节奏和缺口。
- 三条不超过 200 个字符、可直接复制的音乐生成提示词。
- 可审计 JSON、日志和可选静态报告。
- 仅在必要时出现的本地画面复核页。

### 2.2 第一阶段不交付

- 不做常驻本地 Web 服务或独立桌面应用。
- 不要求用户先进入页面再开始任务。
- 不搜索、试听、下载或推荐具体歌曲。
- 不调用曲多多、网易云、QQ 音乐、Spotify、Apple Music 或即梦。
- 不在项目代码中调用 Codex API，不递归创建另一个智能体任务。
- 不生成音乐、音效或最终剪辑时间线。
- 不绑定调用方智能体的模型名称。

## 3. 三种方案与选择

### 方案 A：纯 Skill，无页面

所有确认都在对话中完成。部署最简单，但几十到上百条素材存在大量未知项时，对话会被逐条确认淹没，也不适合并排看代表图。

### 方案 B：Skill 主入口，页面按需出现

日常链路全部由 Skill 驱动；少量问题在对话中确认，大量画面字段才进入临时本地复核页。该方案兼顾日常简洁、批量复核效率和现有审计合同。

### 方案 C：本地 Web 应用，Skill 只是启动器

界面能力最强，但需要维护服务生命周期、状态同步和前端产品，显著扩大第一阶段范围，并把核心体验重新变成网页应用。

选择方案 B。方案 A 作为无浏览器环境下的降级路径，方案 C 不实施。

## 4. 最终用户流程

```text
用户调用 $travel-director
  ↓
Skill 获取素材目录和自然语言描述
  ↓
校验路径、读取缓存、创建或恢复本地项目
  ↓
Scanner 生成技术证据和代表图
  ↓
当前调用方智能体按每批最多 10 条读取联系图
  ↓
逐批写入结构化观察 JSON 检查点
  ↓
用户描述规范化
  ├─ 无关键冲突：继续
  └─ 有关键冲突：在对话中确认
  ↓
观察复核路由
  ├─ 无待确认项：automatic
  ├─ 少量待确认项：对话中确认
  └─ 大量待确认项：生成并打开临时本地复核页
  ↓
deterministic 五桶判断与导演方案
  ↓
一次输出三条音乐生成提示词
  ↓
当前对话返回摘要、提示词、风险和本地制品路径
```

“大量待确认项”的默认定义为超过 5 个字段，或超过 3 条素材需要并排看图。阈值写入 Skill 指令，可后续根据真实使用调整；它不进入核心 Schema。

## 5. Skill 架构

### 5.1 唯一正式入口

仓库内新增可版本控制的 Skill 源：

```text
skills/travel-director/
  SKILL.md
  references/
  scripts/
```

安装目标为：

```text
$CODEX_HOME/skills/travel-director/
```

仓库源是维护真相，安装目录是运行副本。第一阶段不保留两个可独立修改的正式入口；每次更新后必须验证安装副本与仓库源一致。

### 5.2 Skill 与 Python 核心的职责

Skill 负责：

- 与用户交互并取得素材目录、描述和必要确认。
- 调用现有 CLI，而不是重新实现规则。
- 让当前智能体读取联系图并按严格 JSON 合同写观察结果。
- 控制批量大小、检查点、停止门和复核路由。
- 在对话中组织最终结果。

`local-media-scanner/director` 负责：

- 严格 Schema、文件身份、哈希和 Stage Graph。
- Scanner 证据桥接、Brief 规范化和确认。
- 五桶判断、覆盖统计和 deterministic 导演方案。
- 三条音乐生成提示词。
- 条件式复核页的生成、导入和验证。

Skill 不复制 Python 业务规则，Python 核心也不反向调用智能体。

### 5.3 模型策略

- 从哪个智能体调用 Skill，就使用该智能体当前的默认模型与视觉能力。
- `SKILL.md` 不声明固定模型、供应商、API endpoint 或价格。
- Skill 不创建子任务来换模型，也不调用 Codex API。
- 调用方无法读取图片时，回退 `scanner_only + assisted`，并进入对话或页面复核。
- 模型输出只作为候选观察；所有输出必须通过现有严格合同和 unsupported assertion 检查。

## 6. 页面边界

### 6.1 不自动出现的页面

- Brief 规范化页：默认不打开。Skill 在对话中展示规范化摘要，仅在关键冲突时询问。
- 导演桶位复核页：默认不打开。Skill 在对话中展示五桶摘要和关键理由，用户提出修改时再生成复核制品。
- 最终报告页：可以保存为审计/分享制品，但不自动打开，不承担主交互。

### 6.2 可以按需出现的页面

画面复核页只在以下情况出现：

- 待确认字段超过 5 个；或
- 超过 3 条素材需要并排看代表图；或
- 用户明确要求用页面批量修改。

页面是单文件本地静态 HTML，不依赖远程脚本，不启动常驻服务。用户下载 `visual_confirmation.json` 后，Skill 验证哈希并继续原项目。

### 6.3 无页面降级

如果浏览器不可用或用户不想打开页面，Skill 按批在对话中呈现最多 3 条素材的问题。若用户不继续确认，项目诚实停在 `blocked`，保留全部检查点，不伪造完成。

## 7. 当前智能体画面理解协议

- 每条素材只读取一张受控联系图，联系图由 3–5 张代表帧组成。
- 每批最多 10 条素材；完成一批即落一个 JSON 检查点。
- 只允许合同中的字段：技术可用性、内容族、室内外、光线、人物存在/数量档、主体候选、活动候选。
- 不识别人名、精确地点、人物关系或故事身份。
- 低置信度字段必须 `abstained` 或进入 `review_required_fields`。
- 不读取完整视频，不上传源文件，不在一个提示中传入全项目日志。
- 单批结构化输出失败时最多修复并重试一次；再次失败则保存失败制品并转 assisted。

## 8. 最终对话输出

Skill 正常完成后在当前对话中返回：

1. 项目模式：`automatic` 或 `assisted`。
2. 扫描素材数、成功数、待确认数和错误数。
3. 五桶素材摘要及关键理由。
4. 导演主线、章节、情绪推进、节奏策略和素材缺口。
5. 三条可直接复制的音乐生成提示词。
6. `unsupported_inferences`、硬淘汰建议和人工修改摘要。
7. 项目目录、主要 JSON 和可选报告路径。
8. `external_call_count=0` 和未执行的外部服务列表。

Skill 不把完整 JSON 倾倒到对话中，只提供关键结果和可点击文件路径。

## 9. 错误与恢复

- 素材目录不存在或不可读：在扫描前停止，要求用户修正路径。
- Scanner 单文件失败：该素材进入 unavailable，不阻塞其他素材。
- 联系图缺失：该素材进入人工确认，不假装已识别。
- 调用方不具备视觉能力：整体回退 `scanner_only + assisted`。
- Brief 关键字段冲突：不得进入导演推理。
- 人工确认哈希不匹配：拒绝导入，保留原草稿。
- deterministic 方案存在 unsupported inference：Task 失败，不生成音乐提示词。
- 中断后恢复：从最后一个已验证 Stage 或批次检查点继续，不重新处理已完成批次。

## 10. 额度控制

- 复用已有 Scanner 缓存和代表图。
- 一张联系图代表一条素材；每批最多 10 条。
- 逐批 JSON 检查点避免长上下文重做。
- 只有待确认项才进入用户交互，不让用户确认明确字段。
- deterministic Director 和音乐提示词阶段不调用模型。
- 一次任务只做一次完整最终报告，不重复总结中间 JSON。
- Skill 记录实际批次数、处理素材数和失败数，不承诺固定 token 数。

## 11. 验收设计

### 11.1 Skill 合同测试

- `$travel-director` 能从素材目录和描述启动或恢复项目。
- Skill 指令不包含固定模型名、外部 API 或付费服务调用。
- CLI 失败、视觉能力缺失和用户拒绝确认均有明确停止状态。
- 三条音乐提示词一次返回，无额外“选风格再生成提示词”轮次。

### 11.2 条件式页面测试

- 0 个待确认项时不生成、不打开页面。
- 少量待确认项走对话确认。
- 超过阈值时生成本地静态页面。
- 页面图片可见、无远程依赖、JSON 可下载并通过哈希验证。

### 11.3 端到端验收

- 使用冻结 12 条盲测集执行一次完整流程。
- 本地 VLM 已 `not_qualified`，因此实测必须明确记录实际走 `invoking_agent` 或 `scanner_only + assisted`，不能写成 local VLM automatic。
- 完整测试、Skill 静态检查、浏览器条件页检查和 `git diff --check` 全部通过。
- 曲多多、即梦、音乐平台、音乐生成和付费服务均为 `not_executed`。

## 12. 对现有实施计划的修正

现有 V2 的 Task 8 不再以“静态页面交付”为最终目标，改为：

1. 封装并安装 `$travel-director` Skill。
2. 串联现有 CLI 和当前智能体分批观察协议。
3. 实现对话确认与条件式页面路由。
4. 执行冻结盲测和一次完整 Skill 验收。
5. 输出阶段报告并完成第一阶段交付。

原计划中的本地静态页面代码继续保留，但定位为人工复核和验收辅助工具，不再是产品入口。

## 13. 后续阶段

第一阶段 Skill 完成后，具体音乐生成仍由用户把三条提示词交给其选择的智能体或服务。曲库搜索、AI 音乐生成、时间线、音效和编辑器导出必须分别立项，不因 Skill 封装而自动获得授权。
