# 剪映 FCPXML 导入实验

直接写入草稿目录的旧式 JSON 在 macOS 剪映 11.4.0 中报草稿损坏。本实验改用 FCPXML 1.9 交换工程，由剪映自己转换为当前版本的草稿格式。

## 产物

- `TD-P0-12s-FCPXML-20260909-v2.fcpxml`：12 秒时间线。
- `asset/`：3 段视频、1 段音乐和 2 个音效的硬链接。这些文件与原素材共用同一份磁盘数据，不是再复制 224 MB。
- `receipt.json`：生成参数和原始素材记录。
- `build_fcpxml.py`：可重复的生成和静态校验脚本。

已静态验证：XML 语法正确；6 个素材引用均存在；3 个主视频片段；3 个连接音频片段；序列长度 12 秒。用户已于 2026-09-09 确认 macOS 剪映 11.4.0 导入成功；编辑后保存并重开仍未验证。

## 剪映中导入

1. 在剪映首页右上角打开设置，在全局设置中开启“导入工程”。
2. 回到首页，选择“导入工程文件”，选中本目录下的 `.fcpxml` 文件。
3. 如果询问关联素材，选择同目录下的 `asset` 文件夹。
4. 检查是否有 3 段视频、连续音乐和 2 个独立音效；再修改一处音量，退出并重开验证保存。

若导入器报错，保留完整错误文字或截图。不要在草稿目录中手工改名或补文件。

## 依据

扣子官方文档的剪映工程导入流程明确使用 `.fcpxml` 文件和 `asset` 目录：https://docs.coze.cn/cozespace_video

## 本地路径（复跑时）

脚本不再硬编码个人家目录。复跑前请设置：

- `TRAVEL_DIRECTOR_FOOTAGE_DIR`：素材目录
- `TRAVEL_DIRECTOR_AUDIO_ROOT`：音效/音乐库根目录
- 可选 `TRAVEL_DIRECTOR_EXPERIMENT_MUSIC`：试验用音乐 wav 的绝对路径
