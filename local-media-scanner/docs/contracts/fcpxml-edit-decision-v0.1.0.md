# FCPXML edit decision v0.1.0

The model supplies only editorial choices. `travel-director export-fcpxml` owns media probing, range checks, track mapping, gain conversion, hard-linked asset packaging, FCPXML serialization and the validation receipt.

```json
{
  "schema_version": "0.1.0",
  "project_name": "12-second trial",
  "canvas": {
    "width": 1920,
    "height": 1080,
    "fps": 30,
    "duration_seconds": 12
  },
  "clips": [
    {
      "kind": "video",
      "source_path": "/absolute/path/clip.mov",
      "track": "main",
      "timeline_in": 0,
      "source_in": 1,
      "duration": 4,
      "gain": 0
    },
    {
      "kind": "music",
      "source_path": "/absolute/path/music.wav",
      "track": "music",
      "timeline_in": 0,
      "source_in": 0,
      "duration": 12,
      "gain": 0.35
    }
  ]
}
```

`kind` is `video`, `music` or `sfx`. Times are seconds. `gain` is a linear amplitude ratio: `0` is muted, `1` is unity gain. Clips may overlap only when their `track` values differ. The current exporter supports exactly one video track and any number of non-overlapping audio tracks. Every source and timeline range must fit its media or project duration.

Run:

```bash
uv run travel-director export-fcpxml --decision /absolute/path/decision.json --output /new/output/package
```

The output directory must not already exist. A successful run writes `project.fcpxml`, an `asset/` directory of hard links, and `receipt.json`. `fcpxml_generated` means program validation passed; it does not mean Jianying import or edit/save persistence was tested.

## Optional local shot-group binding

An EDL generated by `build-shot-group` includes `shot_group: {"path": "/absolute/group.json", "sha256": "<hash>"}`. This binds the ordered video decisions and canvas to a validated 2–4-shot local combination. Export revalidates the group receipt, its paired fine-review source/evidence hashes and inherited temporal windows, and rejects video EDL drift or unresolved connections before package creation. Existing unbound EDLs remain supported. Group metadata is copied to `shot_group.json` in the package and recorded with its hash and connections in the receipt. Additional audio is allowed without changing the group video decisions or total duration. The invocation session decides the editorial connection; program validation does not certify aesthetic continuity.

## Optional music-adaptation binding

`build-music-adaptation` produces an EDL with `music_adaptation: {"path": "/absolute/adaptation.json", "sha256": "<hash>"}`. Export verifies frozen music, source/project mappings, base-picture identity and immutable revision lineage. Music pauses are explicitly represented as gaps in the music track, not blanket silence. Original-speed source segments can be reordered; unsupported fade plans cannot be exported. Mapping/events/ending/listening status and version differences are included in the receipt and `music_adaptation.json` snapshot. Listening records are attributable user/session claims; program validation cannot prove perception or musical quality. Legacy unbound EDLs stay compatible without gaining this validation claim.

## Optional sound-design binding

`build-sound-design` produces an EDL with `sound_design: {"path": "/absolute/sound_design.json", "sha256": "<hash>"}`. This binds the decision to an evidence-backed sound event design. Export verifies the snapshot file and sha256 hash, revalidates materialized audio clips and non-conflicting track lane assignments, and embeds `sound_design.json` into the output package along with cue roles, auditory depth planes, revision differences and listening statuses in the receipt. Existing picture and music bindings are preserved. Legacy `sfx_cues` remain compatible.

## Optional sound cue resolution

`export-fcpxml --sfx-root <sound-effects-folder>` accepts optional `sfx_cues` alongside `clips`. See the Skill's `references/fcpxml-delivery.md` for fields and supported roles. Cue events are anchored to a video clip index; the exporter resolves exact role/filename keyword matches, rejects missing candidates and invalid time ranges, and expands them into independent SFX clips. `resolved_decision.json` contains the expanded decision; receipt fields `sfx_matches`, `sfx_segments` and `resolved_decision_sha256` preserve the resolution evidence. Input decisions without cues remain supported. SFX are copied, while large video/music assets retain existing hard-link packaging.

Nested audio offsets use the parent's local time origin: `audio offset = timeline position + parent start - parent offset`. The serialized validator reconstructs timeline positions and checks ranges, lanes and gain against the resolved decision. This follows Apple's definition of offset and start in [FCPXML DTD](https://developer.apple.com/library/archive/documentation/Miscellaneous/Conceptual/LegacyDTDsFinalCutPro/FCPXMLDTDv1.7/FCPXMLDTDv1.7.html).
